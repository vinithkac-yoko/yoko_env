# 0013. Phase 3: Qt routines ported, case patterns, how pieces and the library are edited

Status: accepted

**Qt routines are ported when Seamly2D's numbers depend on them.** An elliptical arc is measured by `QPainterPath::arcTo` and `toSubpathPolygons` (`qt_curves_for_arc`, `qt_t_for_arc_angle`, `QBezier::addToPolygon` ...), and a polyline length goes through `QPainterPath::lineTo`, which ignores a point equal to the previous one. We copied those from the Qt 6.4.2 source (the version of the local oracle build) with the same arithmetic, and checked them against Seamly2D itself. The CI oracle runs Qt 6.11.1: if an arc ever differs there, the case test fails and the port moves. Bit-exactness still depends on the platform's maths library (ADR 0011).

**Case patterns.** The basic set and Seamly2D's own patterns test a tool only as far as they use it. A *case pattern* (`fixtures/patterns/cases/<name>.sm2d`, small, written by hand or by a `scripts/make_case_*.py`) exercises one tool in many configurations; `scripts/oracle_cases.sh` has the pinned Seamly2D compute it (`fixtures/oracle/cases/<name>.seamly2d.json`) and the CI oracle job fails if the committed output differs. A case costs minutes and found the `lineTo` behaviour above. Every new tool or edit should get one.

**Pieces are edited as little as possible.** A piece we create has an `id`, a `name`, `version` and its `nodes`; the pinned Seamly2D opens that and computes the same outline, and fills the rest (label data, grainline, seam allowance) in when it saves. We do not invent defaults for those. Creating a piece adds one *modeling* copy per draft object it uses (reusing an existing copy) in the block that holds the first node; deleting the piece drops the copies nothing else uses. A point that is part of a piece cannot be deleted. Pieces are not re-evaluated on every action (about 30 ms each): `session.pieces()` and `piece_issues()` compute them on demand, and `AddPiece` / `SetPiece` check the piece they touch.

**Union is read, not made.** `UnionTool::updateUnion` is ported for the main outline. Creating a union (choosing two pieces and two edges) needs `createUnion`, which also creates the piece with application defaults; that waits until pattern makers say they need it.

**The library keeps metadata beside the pattern, never inside it.** A pattern file stays exactly what Seamly2D wrote. `library/base/*.meta.yaml` point at the locked fixtures; `library/styles/` holds derived styles (a byte-for-byte copy of the parent plus a `.meta.yaml` with `parent`, description, garment type and tags). Storage is behind `DirectoryLibrary` so a database can replace it in Phase 6. Base patterns are locked twice: the library refuses to write them and their sessions are read-only. Search is tag and text matching with a `SearchIndex` interface for embeddings later.

**Copying a piece keeps labels and refuses clashes.** `plan_copy_piece` follows every reference (ids, and names of lines and curves used in formulas) to find what the piece depends on, gives the copies fresh ids and returns actions to apply with `apply_all`. Formulas refer to labels, so labels are kept; a label or a variable the destination already has with another formula makes the copy fail rather than silently rename. Ids appear in some generated names (`Arc_A_12`), so a formula that uses such a name would break; that is not detected yet.
